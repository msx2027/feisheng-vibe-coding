# Agent 编排协议

## 目的

把主对话限制为调度、决策和验收，把具体读取、生成清单、迁移和测试拆成独立的小任务。每个任务只获得完成该任务所需的最小上下文。

## 当前执行模式

当前宿主提供的是独立 Agent 上下文，不提供直接创建/归档 Codex 聊天线程的接口。因此：

- 独立 Agent 上下文视为逻辑隔离的 worker session；
- 任务结果、命令、文件变更和未完成项必须写入 `evidence/`；
- 主 Agent 只验收证据，不把 worker 的自述当作完成证明；
- worker 完成后停止，任务包和证据保留在仓库中，作为可审计归档；
- 没有物理新线程或宿主归档证据时，不得声称已创建或归档真实 Codex 会话。

## 任务包

每个任务使用一个 `tasks/<id>-<slug>.md` 文件，至少声明：

- 唯一目标和不做事项；
- 允许读取和允许写入的路径；
- 输入 revision 或基线 commit；
- 预期产物；
- 验收命令和停止条件；
- 失败时保留的原始输出。

## Worker 回执

worker 必须返回并写入证据：

1. 实际修改的文件；
2. 执行过的命令及退出码；
3. 测试/验证结果；
4. 未验证项和阻塞项；
5. 可复现的下一步建议。

禁止只返回“已完成”、旧日志、静态截图或未绑定 revision 的自述 JSON。

## 主 Agent 验收

主 Agent 按顺序检查：

1. 变更是否只在授权路径内；
2. owner、来源、许可证和调用类型是否完整；
3. 命令是否在当前工作树重新执行；
4. 是否引入第二个 route/truth/runtime/Hook owner；
5. 失败是否触发停止或返工任务。

未通过验收时，不在原任务上继续堆补丁，创建新的返工任务并附带 finding。

## 任务生命周期

```text
planned -> dispatched -> evidence-returned -> accepted
                                      \-> rework-required -> dispatched
```

只有 `accepted` 任务的产物才能进入下一个迁移阶段。
