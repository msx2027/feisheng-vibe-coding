# Routes Registry

This is the single runtime owner of primary route, operation, conditional-lens, and reference-loading mappings. `SKILL.md`, README, validators, and platform adapters must not copy a second route-to-reference table.

The operation/delivery column below is the sole executable projection owner.
`scripts/runtime_decision_contract.py` loads and validates this registry at
runtime, and validators consume that same parser rather than copying the table.
Changing a route contract requires changing this owner and its corpus in the
same diff.

Route names are internal semantic identifiers, not commands or user-facing syntax. Select one primary route from the requested outcome and current evidence, then load only its base owners plus conditionally required owners. A file named in a conditional clause is not a default load.

## Internal Operations And Gates

These are not primary routes:

- `阶段计划` and `执行子阶段` are internal operations of `开发执行`, owned by `references/routes-feature.md` and `references/project-flow.md`.
- `工作室模式` is an optional user-confirmed execution shape inside `开发执行`, owned by `references/studio-execution.md`; it coordinates full user-visible tasks and is not subagent execution.
- `防漂移` is an always-available gate inside the active route; when it activates, load the canonical trigger and procedure from `references/project-flow.md`. Route files contribute only route-specific drift evidence and do not own a second procedure.
- Load `references/plan-artifact.md` only when the selected route will produce or continue a multi-stage executable plan or a user-requested durable plan; that owner decides full eligibility, exclusions, persistence, review, and authorization.
- The Truth Capture Gate is owned only by `references/truth-capture.md`: it decides when conversation conclusions must be proposed for write-back, into which existing or new owner, and requires a confirmed Authorization Card before any truth write. Load it when its Trigger, a Passive Signal, or the Post-Acceptance Drift Check applies; `D0` and ordinary `D1` never load it.
- Audit deliverables are owned only by `references/audit-artifact.md`: every `audit` delivery at module scope or larger runs its three passes and writes its report by default; the report is never remediation authorization or stage write-back. Whole-directory reads of `features/`, `decisions/`, or `audits/` are never a discovery step; open only indexed entries.
- Task depth and bounded discovery are owned only by `references/task-risk-gates.md`.
- Protected risk lanes are owned only by `references/risk-control-gates.md`; risk never raises task depth.
- Test level is owned only by `references/testing-strategy.md` and is independent from task depth.
- Action effect, recovery, operational mode, and authorization are owned only by `references/effect-recovery-gates.md`.
- Truth conflicts and current external-executability questions conditionally load `references/truth-resolution.md`; ordinary current-truth reads do not pay this cost.
- Before render, export, package, archive, signed build, deployment candidate, or another formal deliverable, load `references/formal-materialization.md` and validate the event against Host/Coordinator context. Drafts and probes do not activate it.
- Frontend/backend foundation gates consume the joint decision from `技术选型`. Ordinary local development does not rerun those gates unless current evidence shows a foundation conflict or a missing owner.

## Conditional Development Lenses

They are route-global impact lenses, not user routes, alternate entry points, or keyword triggers. Apply them to analysis, audit, explanation, recommendation, design, implementation, and validation whenever the named impact exists; do not limit them to code changes merely because this section keeps its stable registry heading.

| Lens | Apply when impact evidence shows | Load |
| --- | --- | --- |
| `frontend-design` | Analysis, audit, explanation, recommendation, design, implementation, or validation of a user-visible interaction, journey, layout, navigation, responsive state, accessibility, design-system owner, UI prototype, or design-to-code result. | Eligible bounded `D1` UI bugs stay on the route's compact owners; this lens adds no detailed owner by default. That compact path preserves one established semantic Owner, `T2` RED-before-production when selected, security-impact classification, and fresh verification. Add `references/routes-feature.md` and `references/engineering-execution.md` only for a new journey, information architecture, design-system ownership, prototype or design-artifact judgment, `D2`/`D3`, or failed bounded eligibility; add `references/frontend-skeleton.md` for foundation ownership and `references/ui-design-lifecycle.md` for prototype or design-artifact work. |
| `data-model` | Stored objects, fields, relationships, status, migration, transaction, audit, or retention rules change. | `references/database-design.md`, `references/routes-feature.md` |
| `backend-api` | Business rules, service ownership, API contracts, jobs, callbacks, or server-side enforcement change. | `references/backend-boundary.md`, `references/routes-backend.md`, `references/routes-feature.md` |
| `identity-permission` | Login, roles, visibility, ownership, admin behavior, cross-user access, or allowed actions change. | `references/security.md`, `references/backend-boundary.md`, `references/routes-feature.md` |

| `security-impact` | Identity, permission, ownership, untrusted input, sensitive data, writes, secrets, uploads, public exposure, resource limits, or release settings may change. | `references/security.md`, `references/engineering-execution.md` |
| `deployment-release` | Runtime topology, environment, jobs, domain, public/private exposure, migration, rollback, monitoring, quota, or production cost may change. | `references/routes-release.md`, `references/security.md` |

## Loading Contract

1. When bundled scripts are executable, query the deterministic route catalog and selected route projection first. Only when request or current-truth evidence shows a conditional impact domain, query the lens catalog and every evidence-backed selected lens's exact projection; do not load this complete registry first.
2. The route catalog emits each canonical route row's exact Purpose cell. The lens catalog emits only each canonical lens id and exact Impact cell, never Load. The selected route projection emits exact operation/delivery and Load cells, and each selected lens projection emits exact impact and Load cells. No output may summarize, truncate, or become a second owner.
3. If deterministic projection is unavailable, read this registry once as the fail-closed fallback and mark projection verification `未验证`.
4. Select exactly one primary route and, when defined, one operation, then load base owners from that route's exact projection. Select lens names semantically from impact evidence and load lens owners only after querying each exact lens projection.
5. Classify depth, test/route evidence, action effect, and any active risk lanes using their unique owners.
6. Load conditional owners and lenses only from current files, contracts, runtime, or risk evidence.
7. Do not copy this mapping into `SKILL.md`, README, compatibility docs, or an adapter.
