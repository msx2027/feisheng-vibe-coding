# 开工前架构地基维度

> 读取时机：`architecture-foundation` 已确认触发，需要形成可审阅的 `PASS / BLOCKED` 结论时。

## 最小记录结构

在目标项目 `系统架构.md` 的本轮章节按以下顺序记录：

1. 触发原因、范围、非目标与 sourceRevision。
2. 模块边界：职责、公共入口、允许依赖、禁止直连。
3. 数据与接口：归属、生命周期、统一契约、兼容/迁移；不适用需说明依据。
4. 权限、技术栈与部署：边界、暴露面、回滚。
5. 风险、自动验证、人工确认与门禁结论。

## PASS 判定

以下全部成立才可写 `地基 PASS`：

- 所有适用维度均为已确认或不适用；没有 `BLOCKED`。
- 架构选择与需求、接口契约、项目画像的 sourceRevision 一致。
- 对外兼容、数据迁移、权限和部署风险均已有验证或明确的后续验证路径。
- 用户需要拍板的决策已有明确确认记录。

下列情况必须 `地基 BLOCKED`：决定未定、基线过期、契约冲突、无法解释模块依赖方向，或风险无法给出安全回滚/验证方式。
