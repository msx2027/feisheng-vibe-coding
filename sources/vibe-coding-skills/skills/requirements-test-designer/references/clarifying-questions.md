# clarifying-questions

[读取时机]
    PRD 信息不足、覆盖状态出现 blocked / needs clarification，或需要输出澄清问题模板时读取。

[提问原则]
    只问会改变测试设计、优先级、断言或自动化可行性的高影响问题。
    不把所有未知点都问给用户；低影响问题进入 assumptions。
    小白模糊输入先按 `domain-risk-catalog.md` 判断领域触发器，再从下列问题中选择最少的高影响问题。

[冲突需求]
    - 哪些规则优先级更高：自动处理、人工审批、审计不可变、用户可撤销还是数据一致性？
    - 如果出现部分成功、重复请求、状态冲突或外部服务失败，系统应该回滚、补偿、跳过还是进入人工处理？
    - 已经终态的数据是否允许重新打开、修改、删除或回滚？

[权限 / 角色]
    - 是否存在匿名用户、跨租户、权限撤销、代理登录或管理员越权场景？
    - 每个角色能查看、创建、提交、审批、删除或导出的边界是什么？
    - 权限失败应该返回 401 还是 403？错误体是否有统一 code？

[状态机]
    - 完整状态列表是什么？哪些状态是终态？
    - 每个状态允许哪些操作？非法操作应该返回什么错误？
    - 重复提交、并发审批、撤销、过期和重新打开如何处理？

[API contract]
    - 成功状态码是什么？响应体 schema 是否固定？
    - 错误体 schema、错误码枚举和国际化文案是否固定？
    - 是否要求幂等键、版本号、乐观锁或请求追踪 ID？
    - audit log 是否可查询？字段和保留策略是什么？

[数据与边界]
    - 金额、数量、长度、日期和分页的精度与上下限是什么？
    - 字符长度按 Unicode code point、UTF-16、字节数还是可见字符计算？
    - 空值、空字符串、空白字符、emoji、多语言和超长输入如何处理？

[错误处理]
    - Web 页面错误提示的精确文案和展示位置是什么？
    - 超时、离线、外部依赖失败和部分成功如何恢复？
    - 用户重试后是否可能重复创建或重复审批？

[安全]
    - 是否有多租户隔离、敏感字段脱敏、CSRF、防注入、速率限制和审计防篡改要求？
    - 是否允许从客户端看到资源存在性？403 / 404 是否需要防枚举？

[可访问性]
    - 目标 WCAG 等级是什么？
    - 关键流程是否必须支持键盘和读屏？
    - 弹窗、表单错误、toast 和动态状态变化是否有焦点和 aria 要求？

[性能 / 可靠性]
    - P95 / P99 响应时间阈值是什么？
    - 目标并发量、数据规模和峰值场景是什么？
    - 超时、重试、降级、恢复和可用性目标是什么？

[领域规模]
    - 导入文件最大行数、文件大小、并发导入数和失败任务保留时间是什么？
    - 支付、退款、库存或优惠计算是否有对账规则、幂等键和重复回调处理策略？
    - 移动端最低系统版本、目标设备、弱网条件、权限用途和真机验收范围是什么？
    - AI / RAG 的文档数量、向量规模、模型超时、引用来源和无答案策略是什么？
    - API key / Webhook 的 scope、签名、重试次数、限流窗口和 schema 版本策略是什么？

[兼容]
    - 支持哪些浏览器、设备、系统、屏幕尺寸、语言和时区？
    - 移动端是否是完整支持还是 smoke 支持？

[回归]
    - 是否有历史缺陷、生产事故、客服高频问题或已人工验收路径？
    - 哪些路径必须进入 release smoke？
