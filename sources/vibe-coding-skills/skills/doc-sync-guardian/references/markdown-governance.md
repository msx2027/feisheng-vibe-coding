# Markdown 治理细则

> 读取时机：任务涉及 Markdown 新建、改写、移动、拆分、分卷读取、备份删除或 `.vibe-docs.json.markdownGovernance`。

## 防膨胀与专属目录

- 启用 `markdownGovernance` 后，所有项目 Markdown 统一治理。普通正文超过 8,000 tokens 必须拆分；原文件改为不超过 3,000 tokens 的导航页，并以 `<!-- vibe-markdown-facade: 子目录 -->` 声明正文目录。
- 每个导航页 `X.md` 的正文只能放入同名 `X/` 专属文件夹；正文再次拆分时仍用子导航页的完整同名文件夹。一级总目录优先四个中文概括并与文档同名；无法概括时可加“补充”，但文档和文件夹仍须同名。
- 导航页只放链接和短摘要；每份正文须有全项目唯一的 `vibe-section`、一级标题、反向链接。分卷文件名使用中文短编号加主题，如 `062-输出式学习.md`、`附录-001-术语说明.md`；机器编号只留在 section marker 和索引。

## 检查、备份与删除

- 每次新建、改写、移动或拆分 Markdown 后，交付前运行 `check-markdown-governance.mjs`。检查器只报告并拦截问题，不自行拆分、移动、合并或删除。
- 备份目录登记到 `archiveDirectories` 后不参与日常扫描和读取。用户删除或移出备份后，同步删除目录登记及所有指向该路径的项目内 Markdown 链接。
- 只有用户明确授权迁移、写入已停止、正文完整迁入可定位目标、门面 / 链接 / 索引已验证、源文件不再含需求 / 设计 / 决议、没有并发写入且留有审计记录时，才可删除冗余源文件。

## 精确读取

先读取小导航页，再从中选择一份正文，通过 `resolve-target-doc-context.mjs --markdown <项目相对路径>` 精确申请；禁止遍历同名目录或全文恢复所有分卷。
