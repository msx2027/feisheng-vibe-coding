# codebase-memory-scout 工作流

> 读取时机：实际执行 MCP 侦察、判断是否索引、选择查询工具、输出影响面报告时。

## 工具选择

- `list_projects`：先看目标项目是否已索引，确认项目名。
- `index_repository`：仅在未索引、用户明确要求、结构性大改或结果明显过期时运行。
- `get_architecture`：用于接手大项目、规划已有代码、识别 packages、clusters 和 hotspots。
- `search_graph`：用于找函数、组件、类型、工具脚本、路由和测试入口。
- `trace_path`：用于查 callers / callees、权限链、数据流、跨模块影响面。
- `get_code_snippet`：用于只读关键函数或类，避免整文件读取。
- `search_code`：用于普通文本线索；中文内容不可读、遗漏或乱码时，立即改用 `rg` 和 UTF-8 原文读取。

## 索引规则

- 用户不需要手动执行 `codebase-memory-mcp config set auto_index true`，也不需要手动运行索引命令；scout 启用时自己判断是否需要索引或重建。
- 未索引且用户明确点名 codebase-memory / 代码地图 / 调用链 / 影响面 → 可以索引。
- 未索引且任务是 T2/T3，同时跨模块、调用链不清、入口不明或影响面不明 → 可以索引。
- 普通 T2、已知单文件 bug / review / 补测试 → 先用 `rg`、命中文件和主 Skill 自身上下文，不为了索引增加成本。
- 用户明确说“重新索引 / 用 codebase-memory 看一下” → 可以索引。
- 刚发生目录重组、批量新增、重命名、迁移或大规模生成代码 → 优先重建索引。
- 已索引项目先做保鲜判断：如果目标项目是 Git 仓库，优先用 MCP `detect_changes` 或本地变更信号确认是否存在新增、删除、重命名、批量源码变更或结构性目录变化。
- 少量已知文件的小改不重建索引；用 `detect_changes`、`rg` 和目标文件读取补足上下文。
- MCP 查询明显找不到用户刚新增的函数、组件、测试或路由时，视为结果过期，重建一次索引后再查。
- T0/T1 小改、已知单文件位置、中文规则文档、执行光标、人工验收和 Pencil `.pen` 操作 → 不为了索引增加成本。
- 索引失败时输出“未索引降级”，继续使用 `rg` / 文件读取；不要把工具失败当成主任务失败。

## 查询节奏

1. 用用户目标生成 1-3 个高信号查询，不做无边界搜索。
2. 如果目标是“在哪里改”，先 `search_graph`，再 `get_code_snippet`。
3. 如果目标是“影响哪些地方”，先定位函数，再 `trace_path`。
4. 如果目标是“规划已有代码”，先 `get_architecture`，再按模块补查。
5. 如果目标是“补测试”，先查被测函数，再查 tests 下相似用例。
6. 每次只把候选文件和函数交给主 Skill；不要把 MCP 原始大 JSON 当作最终上下文。

## 禁用与回读规则

- 以下内容必须用 UTF-8 原文确认：`AGENTS.md`、`CLAUDE.md`、`.vibe-docs.json`、执行光标、人工验收记录、中文 docs、Pencil desktop 规则、需求和计划真源。
- MCP 对中文 Markdown 的结果只能当路径线索，不能当可引用内容。
- MCP 输出的调用链是候选影响面；最终仍要读源码、看 diff、跑测试或做 review。
- 任何“已通过 / 已修复 / 人工验收已确认”都不能由 scout 直接声明。

## 输出模板

```text
索引状态：已索引 / 已重建 / 未索引降级 / MCP 不可用降级
侦察结论：最可能相关的模块和原因
建议读取：文件、函数、行号或测试候选
影响面：callers / callees / packages / UI / 数据 / 权限 / 测试
必须回读原文：中文规则、执行光标、验收记录或项目真源
下一步：交给 dev-builder / bug-fixer / code-review / test-automation / dev-planner；只读现状 / 纯影响面报告则本轮到此结束，等待用户确认是否继续
```

## 质量底线

- 不要求用户手动开关 auto_index；索引保鲜由 scout 在启用时自动判断。
- 不让 scout 抢主 Skill 的职责。
- 不用 MCP 结果替代文档真源。
- 不因为 MCP 可用就跳过验证。
- 不在小任务上强行侦察，避免 token 反向增加。
- 不把缺少 MCP 当成阻塞；降级后继续主流程。
- 不把只读现状报告强行交回主 Skill；用户要求继续时重新路由。
