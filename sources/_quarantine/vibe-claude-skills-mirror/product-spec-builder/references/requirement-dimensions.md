# 需求维度清单

> 来源：product-spec-builder/SKILL.md 的 [需求维度清单]。
> 读取时机：生成或补全需求文档，需要逐项覆盖产品、用户、流程、技术、测试。

[需求维度清单]
    在对话过程中，需要收集以下维度的信息（不必按顺序，根据对话自然推进）：

    **必须收集**（没有这些，Product Spec 就是废纸）：
    - 产品定位：这是什么？解决什么问题？凭什么是你来做？
    - 目标用户：谁会用？为什么用？不用会死吗？
    - 核心功能：必须有什么功能？砍掉什么功能产品就不成立？
    - 用户流程：用户怎么用？从打开到完成任务的完整路径是什么？
    - AI能力需求：哪些功能需要 AI？需要哪种类型的 AI 能力？
    - 产品类型：这是 Web 应用、桌面应用、CLI 工具、还是移动端？
    - 技术栈 Profile：platform profile、language adapter、architecture profile、scaffold policy 和 fallback stack 分别是什么？是否使用现有 JS / TS 模板？
    - 执行语境：这是新手单人 `vibe coding`，还是标准团队开发？默认按当前 session / 今天推进，还是按周级排期？
    - 代码组织策略：项目代码默认按什么方式收口？至少问清这是新项目还是在已有项目上继续改；新 Web / Desktop 项目默认 `feature-first`，已有项目默认 `legacy-incremental`，并写清选择原因
    - 术语与命名：核心对象、页面、状态、动作统一叫什么，有哪些禁用别名，代码里分别怎么命名
    - 测试与验证策略：每个新增或改变的可观察行为如何先得到正确 RED？GREEN 的最小实现边界和相关回归是什么？全绿后允许哪些 REFACTOR？是否存在原型、生成代码或配置文件的例外申请，用户是否已明确批准？无法自动化本身不构成例外资格。

    **尽量收集**（有这些，Product Spec 才能落地）：
    - 整体布局：Agent 根据产品类型和功能需求分析合适的布局方案，向用户推荐并确认
    - 区域内容：各区域放什么内容、承载什么功能
    - 控件规范：主要的输入输出方式和交互元素
    - 输入输出：用户输入什么？系统输出什么？格式是什么？
    - 应用场景：3-5个具体场景，越具体越好
    - AI增强点：哪些地方可以加「AI一键优化」或「AI智能推荐」？
    - 技术复杂度：需要用户登录吗？数据存哪里？需要服务器吗？

    **可选收集**（锦上添花）：
    - 技术偏好：有没有特定技术要求？如果没有，是否需要 Agent 基于 platform profile 给出 2-3 个方案？
    - 参考产品：有没有可以抄的对象？抄哪里，不抄哪里？
    - 优先级：第一期做什么，第二期做什么？
