# 口径账本：什么时候入账、审计怎么判读

> 读取时机：本批改动涉及**词位、数字、状态说法**的拍板或替换；或审计时发现同一事实在多处出现且不一致。
>
> 入账规矩的**原文只有一处**：目标项目的 `tools/caliber-ledger.json` 里的 `conventions` 字段（由
> `init-caliber-ledger.mjs` 落盘）。本页不复述那些规矩——复述就是制造第二个会漂移的副本。
> 本页只回答两件机器判不了的事：什么时候该入账，以及审计结果怎么读。

## 一、什么时候入账（时机，不是格式）

**拍板即入账，同批提交。** 用户拍板一个新词位或新数字的那一批改动里，执行会话就顺手把条目写进账本。
判据是一句自问：**这个词／这个数字以后还会被人再写出来吗？**

- 会 → 入账。典型：对外宣传口径、价格、界面固定文案、跨卷重复的阶段叫法、退役词的禁出面。
- 不会 → 不入账。一次性笔误、只在本次出现的临时说明，入账只是给账本添维护面。
- 能单源化或生成化 → 先做生成器，不入账。账本兜底的是「实在要有两份」的场景。

**入账的最小动作**：`id` + `title` + `rule`（一句话说清现行口径是什么）+ `truth.path` 与
`truth.anchorRegex`（真源在哪、用什么串钉住它）+ 至少一个 `mirrors` 或 `scans` 面。
没有真源条目的账本只是把一堆副本登记成另一堆副本。

## 二、审计结果怎么读（判误伤用）

跑完 `check-caliber-ledger.mjs` 拿到红清单后，**先分类再动手**，别看见红就改：

| 红项形态 | 含义 | 正确动作 |
|---|---|---|
| 镜像失步 | 真源已改、副本还旧 | 同批补齐副本。这是账本存在的理由 |
| 禁出词命中 | 退休词又出现在现行面上 | 改词；若该处是历史叙述，登记 `scans.exclude` 并写明理由 |
| 真源／镜像锚点失效 | 文件挪位、改名或措辞已变 | **人工核对后**改锚并注明。锚点失效等于钉子瞎了，不许静默改绿 |
| 账本畸形／正则不可编译 | 账本本身写坏了 | 先修账本。任何模式都不放行 |
| 未知键名 | 键写错（`mirrors`→`mirror`、`require`→`requrie`），这道断言在 JSON 里等于不存在 | 改回正确键名；任何模式都不放行 |
| 条目既无 mirrors 又无 scans | 只钉了真源、没钉任何抄件＝登记了一条没人执行的规矩 | 补镜像或补禁出面；任何模式都不放行 |
| 禁出空跑面 | `scans.include` 的 glob 在一个存在的目录里命中 0 文件（目录改名或 glob 写错，门已瞎） | 把 include 指回真实面；任何模式都不放行。目录本身不存在（如下游没用 GitHub Actions）只打印示众不判死 |
| 挂账待修 | 自称现行却仍是旧口径的活体漂移 | 不阻断，但归属相关批次修净；修净后删除挂账与配套豁免 |

**三条最容易误判的规则**：

1. **行内数字是时点快照。** 文档里「某某契约 54 例」「共 12 处」这类计数，是那一行书写当时的
   快照，不是对现状的持续承诺。数字与现状不符**不算口径漂移**；只有该行自称「现行」「实测于某日」
   而实际失实才算。修复动作是补时点注，不是追刷新值——追刷必然再次漂移，且逐轮追刷是无底洞。
   同理，账本断言只钉存在、不钉数目。
2. **历史材料引用旧词是正当的。** 审计报告、执行记录、归档卷里出现退役词属登记语义，
   走 `scans.exclude` 豁免并写明理由，**不是删史**。删史等于销毁证据。
3. **豁免不得庇护活体漂移。** 反过来，一个自称现行口径的文件里留着退休词，不能用豁免盖过去——
   那要写进 `pendingMirrors` 常驻示众，让它在每次运行时都被念出来。

## 三、和本技能其他流程的分工

- 命名、归位、门面导航、正文重名 → `check-doc-governance.mjs`（结构层，与本账本正交）。
- 词位、数字、状态说法的跨副本一致 → 本账本（内容层）。
- 行为对不对 → 目标项目的行为测试。账本不判行为，也不该判。
- 纯状态描述类（「当前进度」「最近做了什么」）→ 仍靠偶发人工抽检；账本不宣称消灭这类漂移，
  只是把反复出事的那几条钉住。别把账本当全仓一致性证明来汇报。
