- 性质：计划方案（战略层）。执行层细节见 [`20260919-v2-hardening-implementation.md`](20260919-v2-hardening-implementation.md)。任务包不是项目真源。

## 1. 背景与主诉

owner 主诉已确认的需求：让新手小白借助 AI + Agent 做出工程级规范项目。调研定位的两个缺口：

1. **验证缺口**：新手无法独立验证 AI 的工作（安全盲区 / 无验证能力）；7 起公开生产事故逐一复盘均可被一个既有自动化检查拦截。
2. **漂移缺口**：任务执行中的需求漂移与范围蔓延（owner 提供活案例："复核拆分"漂移为"改造工具本身"+R5 回滚浪费 + git 环境连带损伤）。

## 2. 目标

- G1 AI 收工凭据化：收工时刻一次自检、一张凭据（验证/范围/记账三字段），机器可判其存在与形状。
- G2 硬话到位：两条被验证的行为条款补到现有规则够不着的位置（tdd 循环现场、隔离审查者 brief）。
- G3 边界声明全覆盖：dev-builder 流之外的普通任务也有强制边界声明与收工对账（半句补齐，不新建）。
- G4 新手项目护栏加购：密钥/安全扫描以"既有棘轮门禁加购"形态进入目标项目，基线棘轮 + 警告级，不硬阻断。

## 3. 非目标（本期明确不做）

- 不引入 subagent 编排（控制面 `Subagents never write implementation` 既有裁决）。
- 不做记忆库六文件（target-truth schema 已覆盖约 80%，六文件 = 第二文档真源）。
- 不整套搬 spec-kit 模板（与既有四 owner 形成并行真源）。
- 不复活 PreToolUse deny（`contract.json` disabledReason 与 9-18 否决逻辑同闭环）。
- 不新增新手路由 / 新手专用技能目录（`beginner-flow-guide` 退役裁决）。
- 不做提交期预算 / 路径允许集硬阻断（9-18 审计否决项：与 TDD 模板矛盾、误拦致 hook 被禁）。
- 不新建第二个 pre-commit 安装器（`install-hotspot-gate.mjs` 已自动装配，批 C 走加购扩展）。
- 不新建待办账本/第二声明真源（新发现记账挂靠既有 finding deferral 与 `docs/需求变更.md` 语义）。
- 不治认知债（已知未治，见 §8）。

## 4. 第一性原理（方案是以下四条的推论）

1. 新手无法独立验证 AI 的工作 → 真值必须来自机器（命令输出、CI 复跑），不来自 AI 的嘴。
2. AI 会给任何文字规则找局部理由绕过 → 强制放在绕不过的位置：钩子验凭据形状，CI 验凭据真伪；文字只负责闸门到不了的地方（隔离 sub-agent、单技能循环现场）。
3. 规则条数有物理上限，治理自身会膨胀 → 零净增、能并入既有 owner 的不新建、模板投放到目标项目不算包内净增。
4. 决定权归人 → 新发现的事记账等排期，AI 不当场扩散。

| 批 | 内容 | 层 | 成本 | 依赖 |

## 7. 终局条款合规义务（`evidence/20260918-anti-bloat-minimal.md` §4）

- **加规则准入**：批 A 每句新增文字须附「现有规则拦不住的具体逃逸路径 + 实测数据」。逃逸路径已备：①控制面 L28「禁止讨好」够不着自包含 brief 的隔离审查者；②dev-builder 铁律够不着单独走 tdd 循环的场景；③owner 活案例（复核→改造工具漂移）证明普通任务缺边界声明。3-Phase 实测数据在批 A evidence 中补齐。
- **零净增**：批 A 加一句删/并一句，逐条记账。
- **减法机制**：批 B 凭据门禁连续 2 次误拦自动降级为提醒，不在其上叠层。
- **换思路信号**：登记观察项——「不做边界/停止条件」放宽批准率异常升高 → 问题在输入侧（Spec 模板与拆分粒度），回改输入，不加执行期拦截。
